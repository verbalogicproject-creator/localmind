## 1. What v0.1.0 is

A Compose Android client for the Knowledge Foundry that can do one complete, checkable
thing end to end:

> pair → list installed experts → inspect a release → **retrieve evidence** from it →
> have a local model draft an answer from *only that evidence* → have the Foundry
> **finalise the turn and close a receipt over it** → show the answer as grounded, with a
> citation on each claim and the receipt one tap away.

The claim v0.1.0 makes is narrow and is the whole product: **the word "grounded" appears on
exactly one path through the app, and that path has a server-closed receipt behind it.**
Everything else — a model failure, an abstention, a refusal, a drift — renders as itself.

What it is *not*: an agent, a file writer, a tool runner, or a second inference server. It
reads a declared surface and writes nothing.

### Two facts that matter for the tag

1. **The debug variant carries `applicationIdSuffix = ".debug"`.** It is a *different

## 4. Test results in detail

### JVM — 295 tests, 0 failures

Coverage worth naming, because these are the tests that hold the contract:

- **`CanonicalJsonTest`** — the encoder is verified by recomputing the Foundry's *own* four
  published digests. NFC normalisation happens before code-point sorting; the digest covers
  the canonical bytes **without** the trailing LF, which storage and transport then append.
- **`AssistantTurnGoldenTest`** — rebuilds the Foundry's Stage 3D request from the golden's
  own inputs and requires **byte equality**, not field equality. Every value fed in is read
  out of the golden, so what is under test is the construction — key order, nesting, the
  derived answer text, the two-step observation identity, the three self-digests — and not
  anyone's ability to retype a fixture. The response golden decodes strictly.
- **`GroundedAnswerParserTest`** — a citation to an item that was never offered is refused,
  never repaired.
- **`GroundedTurnControllerTest`** — every non-`stop` finish reason stops *before* the wire.
  A truncated generation cannot be receipted.
- **`GroundedTurnPromptTest`** *(new)* — pins the template identity to its bytes, and proves
  no retrieved byte reaches the system message.
- **`GroundedAnswerCopyTest`** *(new)* — what leaves the app when an answer is copied.
- **`RetrievalControllerTest`** — stale-response suppression, the inactive-release gate, and
  which question the displayed evidence belongs to.
- **`SchemaNegotiationTest`** — a tripwire: a schema id cannot join the accepted set without
  a deliberate edit here.

## 5. What is in the frozen scope

**Pairing and session.** Injectable pairing credential — no clipboard, no argv, no disk, no
unauthenticated bootstrap. Neither the pairing credential nor the access token is ever
persisted. Scopes are exactly `capabilities:read`, `expert:read`, `query:read`,
`token:refresh`.

**Expert catalog and release detail.** Strictly decoded; trust state, compatibility,
lifecycle and the four content digests shown full length and copyable.

**Retrieval, inside Expert Detail** (`experts/{releaseId}`, no new route). Explicit
submission only — no request per keystroke. Query text is memory-only: out of Room, out of
`SavedStateHandle`, out of logs, history, crash records and analytics. Offered only for the
**active** release, and refused a second time in the controller. Stale and out-of-order
responses cannot replace newer results (ticket ordering, deliberately not cancellation —
cancelling does not recall bytes already on the wire). Every returned mount snapshot and
evidence item is checked against the requested pack and active release; a mismatch is a
refusal, never displayable evidence.

**Grounded assistant turn** (Stage 3D). Localmind calls llama-swap/LFM; the Foundry never
calls a provider. The model is shown a **numbered** evidence list and writes `[1]` — it
never handles an evidence id, which makes a hallucinated citation *unrepresentable* rather
than merely detectable. Output must finish with `stop` and must parse into cited segments
before anything reaches the Foundry.

**Evidence-only presentation preserved.** No score, no confidence, no narration, no invented
graph labels. `succeeded`, `abstained`, `conflicted`, `refused`, expired-session and
schema-mismatch each have their own wording.

## 7. Changes in this session

`2cca4ea` — 12 files, +570 / −22.

### RC polish, all inside the frozen scope

**1. The answer is copyable.** Every digest in the receipt could be copied and the answer
itself could not, which is backwards: the digests exist to check a claim, and the claim was
behind a screenshot. Copying restores the citation markers the parser stripped and appends a
provenance block — model, template, receipt id, `answer_sha256`. Copying bare prose would
produce a confident, well-formed, entirely uncited answer, which is the exact artefact the
receipt exists to prevent. **The question is deliberately not copied**: the clipboard is
readable by every app on the device, and `request_sha256` already binds it.

**2. The search field is labelled "Question".** The section heading and the field label were
the same four words a thumb's width apart, spending the field's only piece of guidance —
and its accessible name — on a repeat.

**3. The question is named above the answer**, on grounded and not-grounded turns alike. The
box stays editable while an answer sits below it, so an answer drafted before an edit
described the wrong question with nothing on screen disagreeing. "Not grounded" under the
wrong question is the same trap and reads as a verdict on a question that was never asked.

**4. The prompt asks for one claim per paragraph, first.**

### The one contract-visible change

A paragraph **is** a segment — the unit the receipt cites, the unit the screen puts a
citation beside, the unit the Foundry checks for closure. The old rule asked only that
paragraphs be separated by a blank line, and qwen-4b honoured it exactly: one paragraph,
three citations at the end, one segment. That is the footnote-list shape — *these sources
were involved somewhere* — rather than *which claim rests on what*.

The new rule 1 names the thing wanted rather than its formatting, and says it first, where a
small model weights it most.

This changes `template_sha256`, which every receipt records. So `TEMPLATE_ID` was **bumped
in the same change**, and both are now pinned by a tripwire test:

| | template_id | template_sha256 |
|---|---|---|
| before | `localmind/grounded-turn/1.0` | `49a1a6299a159c3c6b100e20505da9479cecfe565745346fde5c469d081ccf0d` |
| **after** | `localmind/grounded-turn/1.1` | `57a736566019fb653408e8bc328c2b4c6962220d29fcacadfccfc9461a273434` |

Receipts written before this change remain checkable against `1.0`; two different templates
behind one name would have made the id/digest pair meaningless to anyone comparing receipts
later. `GroundedTurnPromptTest.the_template_identity_is_pinned_to_its_bytes` fails
deliberately on any future prompt edit, and its message says to bump the id in the same
change.

## 8. The models folder and OpenCL offload — where each lever actually is

You asked for the on-device default folder to move to
`/storage/emulated/0/models/local-mind`, for those models to be auto-configured to their
best settings, and for them to be served with OpenCL offload. **Three of those four levers
are outside the APK**, and one pair of them is jointly unsatisfiable on the path they name.
Here is the map, plainly.

### The GPU path — this is the one your models are already on

The three seeded providers point at **llama-swap on `127.0.0.1:8090`** (`lfm-8b`,
`qwen-4b`, `bonsai-8b`). Every grounded turn ever produced went through it. Localmind is an
HTTP client: it sends `/v1/chat/completions` and reads the reply. **It never opens a model
file, never chooses a backend, and never sets a layer count** — and by direction it must
not, because provider ownership is the boundary the Stage 3D contract rests on.

So for these models, both the folder and the offload live in **llama-swap's config on the
phone**, not in the APK:

```yaml
models:
  lfm-8b:
    cmd: >
      llama-server -m /storage/emulated/0/models/local-mind/LFM2.5-8B-A1B-Q4_0.gguf
      --host 127.0.0.1 --port ${PORT}
      -ngl 99                  # all layers to the GPU
      -c 8192 -fa
    ttl: 300
  qwen-4b:
    cmd: >
      llama-server -m /storage/emulated/0/models/local-mind/Qwen3.5-4B-Q4_0.gguf
      --host 127.0.0.1 --port ${PORT}
      -ngl 99 -c 8192 -fa
    ttl: 300
```

Two conditions, both of which your current setup already meets — the measured numbers in
`ProviderRepository` (22.7–24.9 tok/s for the 8B on Adreno OpenCL) could not exist
otherwise:

- `llama-server` must be **built with `GGML_OPENCL=ON`**. Offload is a build-time backend
  choice; `-ngl` alone does nothing on a CPU-only binary.
- Termux needs storage access (`termux-setup-storage`) to read
  `/storage/emulated/0/models/local-mind`.

`-ngl 99` is the "best configuration" lever you're asking about, together with `-c` and
`-fa`. It is a llama-swap edit, and it takes effect the moment the next swap happens — no
APK rebuild, no Localmind change.

### The in-process path — where the folder change actually landed

`EmbeddedEngine` is the separate **"On-device"** provider (API 30+ only). It is the only
place in the app that has ever had a model folder, so it is where your instruction applies.
It now looks in `/storage/emulated/0/models/local-mind` first and falls back to the
app-private folder.

Two things about it are **stated in the code rather than worked around**:

**It cannot do OpenCL offload, and no setting could make it.** Upstream's binding exposes
`loadModel(path)` and `sendUserPrompt(text)` — no backend selection, no layer offload, no
context length, no thread count. There is no argument to pass. Reaching an OpenCL backend
in-process would mean dropping that dependency and building llama.cpp with `GGML_OPENCL`
ourselves, which is **a new provider, not a configuration** — and explicitly outside the
freeze. Pointed at GPU-chosen models today, it would load them on the CPU and be slower by
roughly an order of magnitude than the path you already have.

**It cannot read that folder in this build.** From API 30 a `.gguf` is not media, so no
granular permission covers it and only `MANAGE_EXTERNAL_STORAGE` — an all-files grant —
would. This app's entire authority story is that it reads a narrow declared surface and
writes nothing; an all-files grant is a deliberate decision, not a line to slip into a
manifest during a freeze. So the folder is looked in, found unreadable, and **said so**:
the status text names both folders and does not assert a cause, because a denied `stat` on
shared storage and an absent directory are indistinguishable from inside the process.

**If you want the embedded engine to actually load from there, say so and it is two
changes:** `<uses-permission android:name="android.permission.MANAGE_EXTERNAL_STORAGE" />`
plus a settings-intent prompt. My recommendation is **not** to, for v0.1.0: it widens the
app's authority for a CPU-only provider that no grounded turn has ever used, in exchange for
nothing the llama-swap path does not already do better.

### Are we aligned?

On the goal, yes — one models folder, GPU-offloaded, sensible per-model settings, and
Localmind pointed at it. On where the work goes: **the folder and the offload are llama-swap
config, not app code**, and the app change you asked for landed on the one provider that
cannot use the GPU. That is the honest shape of it, and it is why "auto-configure best
settings" is not an app feature — it is a `cmd:` line per model, which you can edit and
verify in seconds without a build.

## 11. Known limitations, stated deliberately

- **Semantic and reranker channels are unavailable** in this deployment. Not advertised, no
  fallback behaviour added.
- **`truncation.boundaries` is always empty** — a Foundry bug, not a design. `omission_count`
  is the reliable live signal; the non-empty rendering path is preserved and has fired live.
- **Oversized evidence is omitted whole**, never partially truncated. Nothing reconstructs
  it and the model is never asked to complete it.
- **Client-selected limits are ignored** by the current runtime, which enforces fixed maxima
  (8 items, 8,000 bytes per item, 24,000 total). Localmind sends `limits: {}` deliberately.
- **Empty `selected_text` is valid** for graph-reached identity/provenance-only evidence and
  is presented as an explicit no-quote card.
- **Chat is unchanged.** Direct provider behaviour is untouched by this slice.
