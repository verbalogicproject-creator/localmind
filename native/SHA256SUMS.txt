# Digests of the prebuilt llama.cpp archives the app's Gradle build downloads.
#
# Published by native.yml as release assets under the tag native-<pin tag>, from the
# commit recorded in llama.cpp.pin. Regenerate by bumping the pin, running native.yml,
# and copying what its summary prints.
#
# THIS FILE IS THE TRUST ANCHOR. The archives are fetched over the network and their
# contents are loaded as native code into the app's process, so a mismatch is not a
# stale-cache annoyance -- it is the only thing standing between a swapped download and
# arbitrary code execution. fetchNativeLibs fails closed, and an archive not listed
# here is refused outright rather than trusted because it downloaded successfully.
#
# Format is plain `sha256sum` output, so `sha256sum -c` works on it directly once the
# comments are stripped. Comment and blank lines are ignored by the Gradle parser.
#
# THE TAG DOES NOT IDENTIFY THE ARCHIVE, and that is worth knowing before reading a
# mismatch as an attack. The release tag is `native-<llama.cpp pin>`, so it names the
# UPSTREAM COMMIT and says nothing about how this repo packaged it. Re-running native.yml
# without moving the pin therefore REPLACES the assets under the same tag -- which is
# exactly what happened on 2026-08-16, when the packaging step began bundling the NDK's
# libomp.so and both digests below changed while `b10435` stayed put.
#
# Note both changed. x86_64 gained nothing (no x86_64 library declares NEEDED libomp), yet
# its digest moved anyway, because a zip embeds member mtimes and this build is not
# reproducible. So a changed digest here means "rebuilt", NOT "contents differ" -- do not
# read it as evidence either way without looking inside.
